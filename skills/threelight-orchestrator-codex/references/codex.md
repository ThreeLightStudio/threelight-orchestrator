# Codex 환경

이 설치본은 Codex 전용이다. 앱·CLI·IDE마다 제공되는 세션/서브에이전트 도구가 다를 수 있다. 실제 도구 목록·스키마·반환값을 확인하고 없는 도구를 문서의 이름만 보고 호출하지 않는다.

## 방식 선택

- 독립 작업 대화, 사용자 직접 개입, 장기 유지·재개가 필요하고 세션 관리 도구가 제공되면 [별도 세션](sessions.md)을 선택한다.
- 작은 작업이나 조사·검토 보조에는 [서브에이전트](subagents.md)를 선택한다. 큰 작업 세션이 보조 자식을 사용할 때는 부모 책임과 전체 예약 슬롯을 유지한다.
- 별도 세션 기능이 없는 환경에서 독립성이 필수이면 실행 한계를 설명하고 계획·인계까지 준비한다. 독립성을 조용히 포기해 서브에이전트로 대체하지 않는다. 독립성이 필수가 아니고 승인된 범위에 맞으면 서브에이전트를 사용한다.

## 도구 대응

세션 방식은 현재 제공되는 create/read/wait/send 도구로 대응시킨다. 일부 앱 환경에는 `create_thread`, `read_thread`, `wait_threads`, `send_message_to_thread`가 있다. 프로젝트 세션이면 프로젝트 목록에서 실제 ID를 확인한다. 생성은 비동기일 수 있으므로 결과를 명시적으로 기다리고 pending 식별자를 확정 ID로 사용하지 않는다.

서브에이전트 방식은 현재 제공되는 spawn/follow-up/wait/interrupt 도구로 대응시킨다. `collaboration` 도구가 있는 환경에서는 그 스키마를 따르고, 다른 표면에서는 같은 이름·인수가 있다고 가정하지 않는다. 완료 알림과 새 작업을 트리거하는 후속 요청을 구분한다.

모델과 effort는 [Codex 모델 정책](model-selection.md)을 따른다. 선호 모델을 사용할 수 없는 상황에서는 이를 알리고 현재 사용 가능한 모델·사용자 권한에 맞게 진행한다. 설정 가능한 인수가 없으면 선호 정책을 실제 적용된 설정으로 기록하지 않는다.

앱에서 사용자 소유 작업 대화를 생성한 경우 생성 결과를 앱이 지원하는 방식으로 연결한다. 프롬프트에 명시적 위임, 예약 슬롯, 하위 위임 한도, 파일 범위, 검증을 적어 작업 세션이 승인 범위를 알 수 있게 한다.
