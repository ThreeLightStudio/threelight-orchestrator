# 기록과 재개

사용자가 허용한 영속 위치에 현재 상태와 상세 근거를 분리해 둔다. 기존 형식을 수용하며 새 스키마나 과거 기록 일괄 이관을 강제하지 않는다. 별도 위치가 없고 파일 기록이 허용되면 작업 프로젝트의 `.orchestrator/` 아래 실행별 디렉터리를 사용한다. 공개 저장소에 개인 실행 기록을 올리지 않는다.

현재 상태에는 다음 최소 정보를 둔다.

| 범주 | 내용 |
| --- | --- |
| 목표 | 목표/검토 단위 ID, 범위 버전, 최신 사용자 결정, 전체 완료 기준 |
| 작업 | 작업 ID, 선행 조건, 상태, 소유자, 실제 반환된 작업자 참조, 작업 경로 |
| 입력·검토 | 승인된 입력/결과 버전, 검증 조건, 처리한 결과·증거 참조 |
| 한도 | 초기/현재 전체 동시 실행 상한, 활성 주·보조 작업자, 예약된 보조 슬롯, 확인된 예산 또는 미지정 |
| 다음 행동 | 검토·보완·후속 착수·질문, 상세 근거 위치 |
| 대기·재개 | 확인된 재개 방식, 답변 목적지, 감시가 있으면 해당 실행의 ID·간격·상태 |

긴 결정·원시 로그·모델 선택 이유·검사 출력은 현재 상태에 반복 복사하지 않고 상세 근거를 참조한다. 의미 있는 사건은 작업별로 한 번 기록한다. 입력 승인, 생성, 결과 관찰, 검토 시작/판정, 보완, 소유권 이전, 종료의 실제 관찰 시각과 버전을 남기되 모르는 값을 추정하지 않는다.

재개할 때 실제 작업자 상태와 산출물·입력 버전을 확인한다. 살아 있는 작업자를 찾고 지시할 도구가 없으면 재개 가능한 것으로 보고하지 않는다. 기록을 읽고 새로운 작업자가 이어가는 것과 기존 작업자 자체의 재개를 구분한다. 이전 작업자가 쓰지 않는지 확인한 뒤 남은 범위만 재배정하고 이미 승인된 결과를 다시 만들지 않는다.

환경 변화가 검증에 영향을 주는지 판단한다. 대기 간격 변경 같은 무관한 변화로 기존 증거를 무효화하지 않는다. 연결 실패와 제품 실패를 구분하고 파일·UI·저장된 체크포인트가 기록과 다르면 실제 상태부터 확인한다.

무변화 대기에는 전체 지침·대화·로그 재독, 기록 갱신, 예상 시간 수정, 감시 프롬프트 변경을 하지 않는다. 대기 중인 모든 작업이 인간 답변만 필요하더라도 메인을 확실히 재개할 답변 경로가 없으면 완료로 표시하지 않는다. 감시의 일시 중지와 전체 완료를 구분한다.
