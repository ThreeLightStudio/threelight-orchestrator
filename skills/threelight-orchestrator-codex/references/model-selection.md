# 모델 선택과 effort 결정

## 정책과 실제 설정

명시적 사용자 지정과 선택 권한을 우선한다. 아래는 모델을 지정하지 않은 실행의 선호 정책이며, 현재 도구가 해당 인수를 허용한다는 뜻이나 실제 적용 보장이 아니다.

| 역할 | 선호 정책 | 생성·선택 담당 |
| --- | --- | --- |
| 요청 세션 | 현재 세션 유지 | 실행 범위와 첫 오케스트레이터의 effort 결정 |
| 오케스트레이터 | 별도 GPT-6.1 Sol (`gpt-6.1-sol`) | 요청 세션이 생성하며 지원 effort 선택 |
| 작업자 | GPT-6 Luna (`gpt-6-luna`) 또는 GPT-6.1 Sol (`gpt-6.1-sol`) | 오케스트레이터가 작업별 모델·effort 선택 |

현재 생성·후속 메시지 도구가 특정 모델 인수에 인간의 명시적 지정을 요구하면, 스킬의 기본 정책이나 오케스트레이터의 선택만으로 인수를 지정하지 않는다. 허용되지 않는 인수는 생략해 도구의 기본 설정을 사용하고 선호 정책·전달한 인수·확인 가능한 실제 설정을 구분한다. 확인되지 않은 실제 설정은 미확인으로 남기며 선호 모델이 적용됐다고 주장하지 않는다. 모델 지정이 없다는 이유로 선택 질문을 하거나 실행을 막지 않는다.

사용자가 모델·effort를 고정했다면 보존한다. 이름이 모호하거나 지원되지 않아 지정대로 실행할 수 없으면 필요한 대안만 확인하고 임의로 대체하지 않는다. 명시적으로 허용한 두 작업자 모델 중 하나만 지원되면 지원되는 모델을 선택하고 제한을 기록한다. 요청 세션의 모델은 자동 변경하지 않는다.

## 작업별 선택과 재평가

- Luna: 입력·완료 기준과 구현·검증 경로가 명확한 작업.
- Sol: 원인 불명 조사, 상충 계약, 복잡한 상태·예외 또는 여러 산출물을 연결하는 판단이 필요한 작업.
- 범위·불확실성·결합도·실패 영향·검증 난도를 함께 판단한다. 파일 수나 예상 시간만으로 선택하지 않는다.
- effort는 고정 기본값 없이 해당 호스트·모델에서 지원되는 수준 중 생성 담당 세션이 선택한다. 선택 이유는 한 줄로 기록한다.

위임된 모델 선택 권한 안에서는 작업 성격·범위·권한이 바뀌거나 진단된 추론·설계 문제가 보완 후에도 반복될 때 재평가한다. 실제 설정 변경에도 현재 도구의 권한 조건을 적용한다. 인간의 고정 지정을 바꿔야 하면 먼저 필요한 결정을 확인한다.

연결·권한 오류, 실행 파일이나 도구 부족, 사용자 결정 대기를 모델 성능 문제로 취급하지 않는다. 연결 복구는 실행 참조의 체크포인트와 제한된 재시도 절차를 따르며 근거 없이 모델을 바꾸지 않는다.

## 기록과 재개

역할·정확한 모델 ID·명시 지정/기본 선호/위임의 구분·effort·한 줄 선택 이유를 작업별 기록에 한 번 남긴다. 생성 후 실제 세션 ID·호스트·전달한 설정과 확인 가능한 실제 설정을 연결한다. 현재 상태와 작업 프롬프트에는 필요한 설정 또는 기록 참조만 둔다.

단순 재개나 무변화 감시마다 모델 선택 이유를 다시 작성하지 않는다. 기존 선택·권한·설정을 보존하고 관련 변화가 있을 때만 갱신한다. 오케스트레이터 프롬프트에는 이미 그 역할임을 명시해 다시 오케스트레이터를 생성하지 않게 한다.
