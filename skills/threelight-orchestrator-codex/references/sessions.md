# Codex 별도 세션 실행

사용자가 독립 실행 세션을 요청했거나 승인한 실행 계획이 별도 세션을 포함하는 경우에만 생성한다. 스킬 호출과 계획 논의는 생성 요청이 아니다. 메인이 이미 오케스트레이터이면 자신을 다시 생성하지 않는다.

## 생성·소유권

장기 유지, 사용자 직접 개입, 이후 재개가 중요한 작업은 독립 세션에 배정한다. 프로젝트·체크아웃·worktree·모델·권한은 최신 사용자 결정과 현재 생성 도구의 스키마를 따른다. 참조한 과거 실행의 설정을 새 실행에 적용하지 않는다. 별도 worktree가 요청됐거나 소유권 충돌을 피하는 데 필요할 때만 격리를 선택하고 기존 미커밋 작업을 보존한다.

생성 전에 기존 세션과 기록을 대조한다. 목표/검토/작업 ID·범위 버전, 입력·계약·파일 소유권·완료 기준·검증을 프롬프트에 직접 넣는다. 긴 자료는 접근 가능한 정확한 위치와 버전을 전달한다. 생성 결과의 실제 세션 ID·호스트·작업 경로·입력 버전을 기록한다. 임시 client ID를 실제 세션 ID로 바꾸어 사용하지 않는다.

후속 주 작업 세션은 메인이 생성한다. 작업 세션은 [서브에이전트](subagents.md)를 제한된 보조 작업에 사용할 수 있으며 부모가 결과를 검토·통합한다. 예약된 보조 슬롯과 전역 소유권을 지키고 보조 작업자에게 하위 위임 금지를 전달한다.

## 대기·지시·검토

현재 제공된 `wait_threads` 같은 완료 대기를 우선한다. 반환된 cursor를 다음 대기에 사용해 이미 소비한 결과를 중복 처리하지 않는다. 긴 대기는 나누어 의미 있는 사용자 안내가 가능하도록 한다. 완료 결과는 승인 없이 후속 입력으로 넘기지 않는다.

추가 지시는 인간이 승인한 전송 범위 안에서 현재의 메시지 도구로 보낸다. 이 규칙은 메인→작업자와 작업자→메인 모두에 적용된다. 사용자에게 승인된 작업 계획의 후속 지시 권한을 단계마다 다시 요구하지 않는다. 작업자가 받은 보고 요청은 다른 대화로 메시지를 보낼 권한이 아니다. 결과 수집은 별도 보고 메시지보다 대기 도구를 우선한다.

같은 세션에 보완·통합을 우선 맡긴다. `idle` 상태만 보고 완료로 처리하지 말고 실제 파일·diff·검증 조건을 대조한다. 메인은 작업자 소유 파일을 동시에 수정하지 않는다.

## 장기 감시·복구

사용자가 요청한 지속 감시·예약 실행만 해당 자동화 도구로 설정한다. 도구나 자동 재개 경로가 없으면 지속 실행을 보장하지 않는다. 감시 프롬프트에는 현재 상태 위치·메인/작업자 참조·대기 사유·다음 행동·완료를 소비할 재개 경로를 넣는다. 변화 없는 동안은 조용히 끝낸다.

인간 답변을 기다리는 동안 감시를 중지하려면 실행 중·검토·보완·관찰 가능한 외부 대기가 없고, 답변이 메인을 재개할 경로가 확실하며, 사용자 지속 감시 요청에 반하지 않아야 한다. 전체 완료 시 해당 실행의 감시만 종료한다. 다른 실행이나 과거 자동화는 변경하지 않는다.

연결 실패 시 산출물·마지막 검증·체크포인트와 실제 세션 상태를 비교한다. 이전 작업자가 쓰지 않는지 확인하고 같은 세션을 우선 재개한다. 새 근거 없이 같은 재개를 반복하지 않는다. 새 세션이 필요하면 ID·범위·승인 결과를 유지하고 소유권 이전을 기록한다. 증거가 부족하면 완료를 주장하지 않는다.
