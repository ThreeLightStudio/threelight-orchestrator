# 측정과 스케줄링

작업 경계·검토 순서·병렬성·관리 구조를 판단하거나 결과를 비교할 때만 읽는다. [검토 원칙](operating.md)과 [기록·재개](records.md)를 유지하며 측정만을 위한 작업자·자동화·상세 로그는 추가하지 않는다.

## 최소 기록과 사건 계약

기존 기록에 필요한 필드만 추가한다. 새 스키마·과거 기록의 일괄 이관은 강제하지 않는다.

- 목표·검토 단위·작업의 고정 ID, 합의한 `scope_revision`, 범위·완료 조건·의존성·소유자.
- 실행 시작·ready·배정·산출물 관찰·검토 시작·최초 판정·승인 결과/검증 버전과 관찰/검토 담당자. 재시도·교체는 같은 작업의 attempt·thread·소유자를 연결하며 목표/검토 ID와 최초 판정을 초기화하지 않는다.
- 실제 usage의 출처·집계 범위·counter ID·기준/후속값, 공동 비용, 중복 조정의 사건·원인·근거 참조. 원시 로그는 복사하지 않는다.

사건 종류는 ready·dispatched·artifact_observed·review_started·review_decided·goal_verified·blocked/unblocked다. 각 사건에 목표/검토/작업 ID·scope revision·종류·observed_at·관련 입력/산출물/증거 버전을 연결하며, 해당 시점에 없는 버전과 source_at은 미확인 또는 해당 없음으로 둔다. blocked/unblocked에는 사유와 시작/해제를 연결한다. 같은 결과/증거의 사건은 한 번만 기록한다.

상태 전환·최초 판정·새 산출물/증거·범위/계약/소유자 변경만 사건으로 남긴다. 중복 신호·무변화 확인은 새 사건이 아니다. 결과를 보고 검토 ID를 유리하게 분할/병합하지 않는다. 범위 변경은 revision과 영향을 연결하고 이전 판정을 보존한다.

`source_at`은 출처의 실제 발생/제출 시각, `observed_at`은 담당자가 처음 확인한 시각이다. 서로 대체하지 않고 다른 시계 기준을 섞어 지연을 계산하지 않는다. 시각·usage·권한은 미확인을 보존하고 도구 보고·직접 관찰·추정을 구분한다. 추정을 실측으로 계산하지 않는다. 과거 누락은 재개/다음 전환에 필요한 부분만 복원하며 현재 시각으로 채우지 않는다.

레거시 기록에 목표/검토 ID가 없었으면 이미 확인한 작업·소유자·세션·승인 결과에 안정된 식별자를 연결하고 재개 시 부여한 출처를 표시한다. 기존 ID가 확인되면 그대로 보존한다. 지표만을 위해 과거 턴을 역추적하지 않으며 이전 최초 판정·시각은 미확인으로 남긴다. 누락이 실제 소유권·의존성 식별을 막을 때만 관련 기록을 좁게 확인한다. 새 ID로 기존 승인을 다시 검토하거나 최초 통과로 세지 않는다.

## 7개 지표와 오판 방지

분모·scope revision·측정 기간을 함께 둔다. 목표와 작업/세션/attempt 수를 혼동하거나 다른 난이도·범위를 단순 순위로 비교하지 않는다.

| 지표 | 정의와 해석 |
| --- | --- |
| 검증된 목표 완료 | 해당 revision의 목표 중 필수 검증·통합 검토 통과 수/전체 목표. 세션 완료·커밋·`idle`로 대신하지 않고 revision별 수를 중복 합산하지 않는다. |
| 첫 검토 통과 | 사전에 정한 고정 검토 단위의 최초 판정 중 통과 수/판정 수. 미판정은 별도다. 증거 부족·보완 필요의 최초 판정도 비통과로 남기되 구현 결함과 구분한다. 재시도·교체·보완으로 최초 실패를 지우지 않는다. |
| 전체 완료 시간 | 메인이 승인된 범위의 실행을 개시한 시점→목표의 필수 검증·통합 검토 통과. 첫 작업자 시작으로 기준을 늦추지 않는다. 미완료는 현재 경과와 상태. 사용자·외부 대기도 포함하고 원인을 구분하며 임의로 차감하지 않는다. |
| 배정 지연 | 선행 승인·입력·권한이 충족된 ready→메인의 실행 요청을 도구가 수락한 배정 시점. 슬롯은 ready 조건이 아니므로 슬롯 대기도 포함한다. 생성 요청·수락된 큐 ID·실제 작업자 시작을 구분하며 배정 후 설정/시작 대기를 이 지표와 섞지 않는다. 수락 시각 미확인은 배정 확인의 관찰 기준임을 표시한다. ready 해제/재성립 구간과 사유도 구분한다. |
| 검토 지연 | 검토 담당자의 첫 산출물 관찰→검토 시작/승인까지를 각각 측정한다. 실제 제출 시각과 구분해 발견 지연을 섞지 않는다. 최초 관찰 시각이 없으면 미확인으로 둔다. |
| 목표별 토큰 사용량 | 메인·분야 조정자·작업자의 실제 usage를 중복 제거한다. 귀속 불가 비용은 shared로 남긴다. 모델·effort·범위를 같이 표시한다. 호출 수·문자 수를 실제 토큰으로 보고하지 않는다. |
| 불필요한 조정·보완 | 근거가 확인된 중복 배정·검토·인계·재읽기·재작업의 건수+원인+증거. 필요한 검증·계약 재검토·새 진단의 보완은 제외한다. 원인 불명은 후보이며 낭비로 확정하지 않는다. |

첫 검토 판정은 발생 당시 revision에 귀속한다. 후속 revision에서는 원 판정의 revision을 표시해 참조하며 새 최초 판정으로 다시 합산하지 않는다. 새 완료 조건의 미판정과 기존 조건의 현재 유효한 승인 결과를 구분하고 이전 실패를 지우지 않는다.

사용자·외부 대기는 사유별 구간과 중첩을 표시한다. 필요 시 같은 시계의 구간 합집합을 계산하되 전체 경과시간에서 빼지 않는다. 병렬 작업 시간·도구 wait 합계를 벽시계 시간에 더하거나 조정 오버헤드 비율로 해석하지 않는다.

토큰은 출처의 정의를 따른다. input/output에 cached/reasoning이 포함되면 다시 더하지 않는다. 포함 관계 미확인은 분리 표기하고 총량을 확정하지 않는다. 같은 호출의 최종 usage와 누적 counter를 이중 합산하지 않는다. 누적 값은 동일 출처·실행·집계 범위의 delta이며 기준값이 없으면 미측정 구간을 표시한다. reset은 새 구간으로 나누고 음수 delta를 사용하지 않는다. fork의 복사된 선행 counter·상하위 중복 usage는 한 번만 세되 새 요청의 실제 입력 재처리 비용은 제거하지 않는다. shared 비용은 목표마다 전액 배분하지 않고 전체 합계에 한 번 포함한다. usage 미확인 상태에서 한도 준수·절감률을 보장하지 않는다.

성공 99.9%·최대 가동률·idle 0·무조건 scale-out을 보편 목표로 두지 않는다. 검증 공백·복구·재작업률은 추가 필수 KPI가 아니며 필요 시 사건을 확인한다.

## 작업 경계·검토 우선순위·동시 실행

검토 가능한 결과로 나눈다. 같은 계약·소유권의 작은 연속 작업은 생성 전에 합칠 수 있으나 사용자 지정 단계/세션 분리와 배정한 소유권을 보존한다. 관리 트리는 보고/검토 책임, 의존성 DAG는 입력/승인 조건이다. 부모 세션 존재를 선행 조건으로 만들거나 트리 순서대로 실행하지 않는다.

사용자의 우선순위·시간·토큰·동시 실행 한도를 우선한다. 미지정 시 계획의 소유권 비충돌 최대 병렬 묶음 크기를 초기 soft 상한으로 삼는다. 실행 중·시작 요청 처리 중을 세며 분야 조정자는 포함, 메인은 제외한다. 완료 기록·`idle`을 CPU 사용이나 실패로 해석하지 않는다. 근거/적용 범위를 기록하고 확인된 도구/환경 제한을 지킨다. `wait_threads`의 조회 대상 8개는 실행 슬롯 수가 아니다. soft 상한은 메인의 배정 정책이며 도구의 슬롯 예약/강제 제한 기능을 가정하지 않는다.

검토는 사용자 우선순위→핵심 의존성을 푸는 결과→같은 우선순위의 오래된 결과 순이다. 모르는 소요시간으로 임계 경로를 만들지 않는다. 무관한 작업을 기다리지 않고 선행 미승인 작업은 배정하지 않는다. 실패의 종속 분기만 보류하고 계약 영향 분기만 재검토한다.

soft 상한은 의미 있는 전환에만 조정한다. 검토 적체·소유권 충돌·확인된 한도 도달 시 신규 배정을 줄이거나 보류한다. 검토 대기 한 건만으로 처리 여력 부족을 확정하지 않고 후속 차단·대기 증가·검토 처리 여력의 근거를 본다. 상한을 낮춰도 실행 중인 소유자는 자동 종료하지 않는다. 적체/충돌 해소와 처리 여력이 확인되면 준비된 독립 작업을 기록된 상한까지 다시 배정한다. 상한 확대는 계획 재평가 때만 하며 사용자/환경 한도를 지킨다. 사용자 지정 0은 신규 배정 보류로 따른다. 미지정 시간/토큰 한도나 실제 슬롯·usage 미확인을 여유로 추정하지 않고 무변화 확인에는 상한/기록을 갱신하지 않는다.

## 분야 조정과 보조 위임의 한도

기본은 메인이 주 작업자를 직접 관리하는 구조다. 분야별 검토 병목이 측정되고 소유권·계약·검토 책임이 명확하면 메인이 분야 조정자에게 검토·증거 정리를 맡길 수 있다. 분야 조정자는 전역 계약을 바꾸거나 주 작업자를 생성하지 않는다.

작업자 아래 제한된 보조 위임을 허용하는 환경에서도 예약된 전역 슬롯과 한 단계 한도를 지킨다. 조정 계층과 보조 계층을 중첩해 깊이를 늘리지 않는다. 추가 인계·토큰·대기를 포함해 비교하고, 이익이 관측되지 않으면 미착수 작업부터 기본 구조로 돌아간다. 실행 중인 작업을 자동 종료하지 않는다.

## 공개 1차 근거

설계 원리의 근거다. 각 실행 방식의 지속성·제어 방식은 다르며 SDK/프레임워크·자동 슬롯/트레이스/체크포인트를 가정하지 않는다. 본문의 운영 정책은 보편 표준·절감률이 아니다.

- [Google SRE — Service Level Objectives](https://sre.google/sre-book/service-level-objectives/): 사용자별 지표·목표·측정 조건을 정하고 소수의 SLO와 현실적인 목표를 선택한다.
- [Google SRE — Monitoring Distributed Systems](https://sre.google/sre-book/monitoring-distributed-systems/): 단순한 감시를 권하며 100% 가동률 전에도 성능이 저하될 수 있음을 설명한다.
- [Apache Airflow — Metrics](https://airflow.apache.org/docs/apache-airflow/stable/administration-and-deployment/logging-monitoring/metrics.html): scheduled·queued·running 시간과 scheduler 비용을 구분한다. 모든 대기는 같은 원인이 아니다.
- [OpenAI — Evaluate agent workflows](https://developers.openai.com/api/docs/guides/agent-evals): handoff·도구 선택·정책 준수와 전체 실행의 회귀를 구조화된 기준으로 평가한다.
- [OpenAI — Multi-agent](https://developers.openai.com/api/docs/guides/responses-multi-agent): 독립된 bounded 작업에는 병렬성이 유리하지만 토큰 증가·순차 의존·공유 상태·외부 병목을 고려한다.
- [Anthropic — Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system): 명확한 위임 경계, 산출물 참조 인계, 완료 결과 평가와 동기 대기 병목을 설명한다.
