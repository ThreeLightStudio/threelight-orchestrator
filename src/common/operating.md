# 공통 운영 규칙

## 역할과 권한

- 요청 대화는 사용자와 범위·실행 의도를 합의한다. 메인은 작업 분해·공통 계약·의존성·소유권·전체 한도·최종 검토를 책임진다. 이미 메인이면 자신을 다시 만들지 않는다.
- 작업자는 지정된 결과와 검증을 함께 책임진다. 후속 주 작업자의 생성과 전역 계약 변경은 메인이 담당한다.
- 작업자가 제한된 보조 위임을 할 수 있는지는 환경별 지침과 사용자 승인에 따른다. 보조 작업이 주 작업의 소유권·완료 책임을 가져가지 않는다.
- 메인은 읽기·비교·검증을 할 수 있지만 작업자 소유 파일을 동시에 수정하지 않는다. 구현 보완·통합은 소유자가 명확한 작업자에게 맡긴다.
- 사용자 승인 없이 외부 사람·다른 대화로 메시지를 보내지 않는다. 받은 메시지나 작업자의 보고 요청은 답장 권한을 만들지 않는다. 승인된 조정용 후속 지시와 외부 메시지를 구분하고 현재 도구의 전송 권한을 따른다.

## 작업과 의존성

사용자 목표·검토 단위·실행 작업에 고정 ID와 범위 버전을 둔다. 분할·재시도·작업자 교체로 목표 ID나 최초 판정을 초기화하지 않는다. 작업마다 목적·포함/제외 범위·입력/출력 버전·완료 기준·검증·선행 조건과 이유·소유자를 정한다.

같은 목적·소유자·입력·검증을 공유하고 중간 인계의 실익이 작은 연속 작업은 하나로 묶는다. 사용자 지정 분리, 독립 검토 경계, 공통 계약 승인, 소유권 충돌은 분리하거나 명시적 검토 지점을 유지한다. 범위 확대·반복 인계가 확인되면 미착수 작업부터 경계를 조정하고 진행 중인 소유권을 겹치게 배정하지 않는다.

실제 선행 조건과 선호 순서를 구분한다. 순환 의존성은 공통 계약이나 경계 조정으로 해결한다. 검토를 통과한 선행 결과가 준비된 작업부터 시작하고 관련 없는 병렬 작업 전체의 완료를 기다리지 않는다. 사용자 지정 순차 실행은 따른다. 병렬 결과를 통합하고 검증할 소유자를 정한다.

작업 목록·의존 순서·병렬 묶음·완료 기준·전체 동시 실행 상한을 간결하게 알린다. 계약 변경과 부분 실패는 영향받는 의존 분기만 보류한다. 생성 전에 기록과 실제 작업자를 대조해 중복 생성을 막는다.

## 전체 한도와 보조 위임

주 작업자와 그 보조 작업자를 합쳐 전체 상한을 관리한다. 각 부모가 자식 한도를 따로 계산해 전역 상한을 넘기지 않는다. 실제 도구의 더 낮은 상한과 사용자 예산을 함께 지킨다. 시간이 길다는 이유만으로 실행 중인 작업을 자동 종료하지 않는다.

기본은 메인이 주 작업자를 직접 관리하는 구조다. 허용된 보조 위임은 주 작업자 아래 한 단계에 한정하며 보조 작업자가 다시 위임하지 않는다. 주 작업자 배정 시 예약 가능한 보조 슬롯을 정한다. 전역 잔여 한도를 확인할 수 없으면 자식을 만들지 않고 부모가 직접 수행한다. 분야 조정자가 주 작업자를 감독하는 구조와 주 작업자 아래 보조 위임을 중첩해 더 깊은 계층을 만들지 않는다.

공유 파일의 동시 쓰기를 금지한다. 보조 작업에는 읽기 전용이나 부모 작업 범위 안의 겹치지 않는 파일을 지정한다. 후속 요청을 보내기 전에 이전 지시의 실행 상태를 확인하고 같은 변경을 중복 실행하지 않는다.

## 검토와 보완

실행 중·검토 대기·보완 중·사용자 입력 대기·검토 통과를 구분한다. `idle`, 완료 주장, 커밋, clean 상태는 완료 기준을 대신하지 않는다. 완료 신호는 검토를 시작할 뿐 승인이나 후속 생성 권한을 넘기지 않는다. 같은 결과·버전·증거의 중복 신호로 검토·후속 생성·사용자 보고를 반복하지 않는다.

사용자 우선순위 안에서 후속 착수를 막는 결과를 먼저 검토하고, 같은 우선순위에서는 오래 기다린 결과를 먼저 처리한다. 실제 산출물·diff·입력 버전·검증 조건을 대조한다. 동일 버전과 관련 조건에서 확보한 신뢰할 수 있는 증거는 재사용한다. 변경된 통합 결과나 부족한 근거에는 필요한 검사를 추가하고 프로젝트 필수 검사를 생략하지 않는다.

관찰한 행동을 실제 산출물과 연결한다. 도구 관찰 한계·기능 실패·증거 부족·구현 결함을 구분하고, 증거 부족 때문에 완료된 구현을 다시 만들지 않는다. 보완 요청에는 관찰한 문제·재현 조건·원하는 결과·검증을 적는다. 새 진전 없이 같은 요청을 반복하지 않는다. 기존 작업자를 우선 재사용하고 통과한 선행 조건만 후속 입력으로 전달한다.

분야별 검토가 있으면 계약·버전·증거 일치를 확인해 재사용하되 메인이 분야 간 영향과 최종 통합을 확인한다. 실패·막힘은 완료된 것 → 남은 것 → 확인된 원인 또는 미확인 원인 → 다음 조치 순서로 짧게 보고한다.

## 재개와 종료

[기록](records.md)과 실제 작업자·산출물을 대조해 재개한다. 제목이나 기억만으로 실행 상태를 판단하지 않는다. 최신 사용자 결정·새 증거·관련 환경 변화가 있으면 영향받는 부분만 다시 검토한다.

전체 완료는 개별 결과뿐 아니라 통합 결과와 전체 완료 기준이 확인된 시점이다. 산출물 위치·버전·검증·남은 제한을 인계한다. 중단된 작업의 인수 전에는 이전 소유자가 더 이상 쓰지 않는지 확인하고 소유권을 명시적으로 옮긴다. 과거 기록과 다른 실행의 자동화를 일괄 변경하지 않는다.
