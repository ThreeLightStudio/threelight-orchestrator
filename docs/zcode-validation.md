# ZCode 실검증

이 시험은 실제 ZCode 도구를 가진 사용자 대화에서 실행합니다. 설치 성공과 실행 지원을 구분하고, 실제 반환값과 산출물을 확인합니다. 개인 세션 ID나 대화 전체를 공개 저장소에 올릴 필요는 없습니다.

## 준비

이 저장소에서 `node bin/tlo.mjs install --target zcode`를 실행한 뒤 ZCode에서 새 대화를 시작하거나 스킬 목록을 갱신합니다. 기존 설치본이 있으면 먼저 내용을 확인하고 필요할 때만 `--replace`를 사용합니다. 스킬 호출 문법이 없으면 `skills/threelight-orchestrator-zcode/SKILL.md`의 실제 위치를 지정해 읽도록 요청합니다.

## 1. 논의만 요청

아래 요청을 먼저 보내고 작업자를 생성하지 않는지 확인합니다.

> threelight-orchestrator-zcode 스킬을 읽고 간단한 병렬 조사 작업의 범위를 함께 논의해 주세요. 아직 실행하거나 에이전트를 만들지 마세요. 사용할 수 있는 실행·추가 지시·완료 확인 기능은 현재 도구 목록에서 확인 가능한 것만 설명해 주세요.

## 2. 실제 실행

다음 요청으로 실행을 명시적으로 승인합니다. 일반 프로젝트 파일에 접근할 필요가 없습니다.

> 이제 격리된 임시 작업 폴더에서 시험을 실행해 주세요. 이 시험의 메인과 서브에이전트는 현재 모델을 계승하고, 활성 작업자는 최대 2명이며 하위 위임은 금지합니다. 메인이 fixture.txt에 확인 문구 TLO-ZCODE-731과 숫자 17, 25를 저장하세요. 읽기 전용 서브에이전트 2개를 만들어 한 작업자는 파일의 확인 문구를 읽고, 다른 작업자는 두 숫자를 읽어 합을 구하게 하세요. 생성·결과 수집에는 현재 실제 도구만 사용하세요. 메인은 실제 입력과 반환값을 검토한 후 result.json에 검증된 결과와 근거를 저장하세요. 사용자 프로젝트·네트워크·예약 실행·다른 세션 메시지는 사용하지 마세요. 도구명, 성공한 동작, 산출물 내용, 지원하지 않는 동작을 보고해 주세요.

검토자는 입력 파일과 결과 파일을 직접 대조합니다. 단순한 완료 주장만으로 통과하지 않습니다.

## 3. 동일 작업자 후속 요청

다음 요청에서는 최초 확인 문구를 다시 보내지 않습니다.

> 완료된 첫 번째 서브에이전트에게 최초 지시의 확인 문구를 다시 묻는 후속 요청을 보내 주세요. 현재 도구가 완료된 작업자를 다시 실행할 수 있을 때만 시도하세요. 동일 작업자 재개가 불가능하면 가능하다고 주장하거나 새 작업자를 같은 작업자라고 부르지 말고 그 제한을 기록하세요. 실제 도구 반환과 응답으로 결과를 보여 주세요.

후속 요청이 지원되지 않는다는 관찰도 유효한 결과입니다. 그 경우 신규 작업자가 기록을 통해 이어갈 수 있는 범위를 별도로 설명합니다. 같은 부모 안의 성공을 앱 재시작 이후 복구 지원으로 확대하지 않습니다.

## 4. 완료·의존성 확인

> 작업자가 완료라고 말했지만 검증 산출물이 없다는 상황을 가정해 주세요. 그 결과가 필요한 후속 작업을 곧바로 시작해도 되는지, 이 스킬에 따라 현재 상태와 다음 조치를 설명하세요. 실제 새 작업자는 만들지 마세요.

## 결과 공유

아래 항목을 현재 Codex 대화에 텍스트로 전달해 주세요. 실제 도구 응답과 파일 내용을 근거로 작성하고, 미확인 항목을 통과로 표시하지 마세요.

- ZCode 버전 또는 확인 가능한 클라이언트 정보, 사용한 스킬 이름
- 논의 단계에서 작업자를 만들었는지
- 생성·결과 수집에 실제 사용한 도구와 성공/실패
- fixture.txt와 result.json의 내용
- 동일 작업자 후속 요청의 도구·응답 또는 지원되지 않는다는 근거
- 미검증 완료 결과를 승인했는지, 후속 의존 작업을 보류했는지
- 앱 재시작 이후 복구·예약 실행은 이 시험에서 미검증임을 명시

실제 결과를 검토한 뒤 공개 검증 현황을 갱신합니다. 실제 ZCode 검증이 끝나기 전에는 정식 지원 완료나 첫 안정 태그를 주장하지 않습니다.
